# Codex 工作日报 Skill 设计

## 目标

创建一个个人 Codex Skill。用户手动输入“总结今天的 Codex 工作”后，Skill 汇总当前 Mac 上当天全部 Codex 工作对话，生成 Markdown 日报与个性化 Codex 使用优化建议，并立即通过固定钉钉机器人单聊发送到用户预先绑定的钉钉账号。

本功能不创建定时任务。手动触发本身同时代表生成和发送授权，生成成功后不再请求二次确认。

## 范围

### 包含

- 按 `Asia/Shanghai` 时区汇总指定日期，默认当天 `00:00:00` 至 `23:59:59`。
- 覆盖本机 `~/.codex/sessions` 与 `~/.codex/archived_sessions` 中所有工作区的会话。
- 优先使用当前 `~/.codex/state_5.sqlite` 获取线程标题、项目目录、模型、推理强度、归档状态和会话文件路径；版本变化时发现包含兼容 `threads` 表的 `state_*.sqlite`，不永久硬编码版本号。
- 按项目聚合目标、完成事项、代码与文件变更、测试与交付、关键决策、当前阻塞及下一日待办。
- 基于当天真实对话生成 Codex 使用优化建议，覆盖模型选择、提示词、上下文承接、对话边界及其他高价值改进机会。
- 生成钉钉 Markdown，并通过 `dws chat message send-by-bot` 单聊发送。
- 通过本地发送账本对相同来源内容进行去重；有新增对话时允许发送更新版。

### 不包含

- 云端账户中未同步到当前 Mac 的对话。
- 已彻底删除且本机无会话文件的对话。
- 自动定时执行、离线补跑或后台监控。
- 钉钉群推送、钉钉文档追加或钉钉日志提交。
- 完整对话归档或逐字转发。

## 触发与用户体验

主要触发语句为“总结今天的 Codex 工作”。语义相同的请求，例如“生成今天的 Codex 日报并发到钉钉”，也应触发 Skill。

执行顺序：

1. 解析当天本机 Codex 会话。
2. 生成标准化工作记录。
3. 归纳工作进展，并执行证据驱动的 Codex 使用复盘。
4. 渲染包含工作日报和优化建议的 Markdown。
5. 验证固定机器人与固定收件人配置。
6. 检查来源摘要是否已成功发送。
7. 未重复时立即机器人单聊发送，不请求二次确认。
8. 在当前 Codex 对话中显示相同日报及发送状态。

如果相同来源内容已经发送，Codex 显示“已发送，无新增内容”，不重复投递。如果来源中出现新对话或新消息，则生成新的来源摘要并发送更新版。

## 架构

个人 Skill 安装到 `~/.agents/skills/codex-daily-summary/`，由四个边界清晰的部分组成。

### Skill 指令

`SKILL.md` 负责：

- 定义触发条件、日期解释和完整工作流。
- 调用解析器并验证其结构化输出。
- 根据日报内容契约完成工作归纳、Codex 使用复盘和 Markdown 渲染。
- 调用钉钉发送器，并向用户报告发送结果。

Skill 不直接手写解析 JSONL，不在正文中保存机器人编号、用户 ID 或认证信息。

`references/codex-optimization-rubric.md` 保存可独立更新的复盘判定标准。它以官方 Codex 指南和当前环境可验证的模型能力为依据，不把某个模型名称永久写成唯一最佳选择。日常运行不依赖联网更新；如果无法确认具体模型能力，只推荐“日常快速”或“复杂深度”等能力档位，不编造模型名称、价格或可用性。

### 会话解析器

`scripts/extract_codex_day.py` 负责只读数据提取，输入为日期、时区及可选 Codex 根目录，输出稳定 JSON。职责包括：

- 查询线程索引并定位活动与归档会话文件。
- 解析日期范围内的 JSONL 事件。
- 仅保留用户请求和可用于工作总结的 Codex 回复。
- 排除系统提示、开发者指令、工具调用原始日志、内部推理和环境注入信息。
- 按线程输出标题、项目目录、时间、所用模型、推理强度、用户目标、结果文本和采集告警。
- 对疑似密钥、令牌、Webhook、机器人编号和用户 ID 进行脱敏。
- 计算来源摘要，供发送幂等使用。

解析器不得修改 Codex 数据库或会话文件。

### 钉钉发送器

`scripts/send_dingtalk.py` 负责确定性投递，输入为 Markdown 文件、日期和来源摘要。职责包括：

- 从个人配置加载唯一允许的机器人编号和唯一允许的收件人 ID。
- 拒绝命令行或日报正文临时覆盖收件人。
- 基于日期和来源摘要生成稳定投递键，并在调用钉钉前写入本地发送账本。
- 使用 `dws chat message send-by-bot --format json` 发送 Markdown。
- 内容过长时按项目边界拆分为有序消息，并为各分片生成稳定投递键。
- 记录每个分片的 `PENDING`、`SENT`、`FAILED` 或 `UNKNOWN` 状态。机器人发送接口不支持服务端幂等键，因此超时、响应解析失败等结果不明确的情况不得自动重试。

发送器不得使用 curl、浏览器或直接 HTTP API 操作钉钉。

### 个人配置与状态

个人配置保存在 `${XDG_CONFIG_HOME:-~/.config}/codex-daily-summary/config.json`，至少包含：

- `robotCode`：已存在且当前账号可用的钉钉机器人编号。
- `recipientUserId`：用户本人的钉钉 userId。
- `timezone`：默认 `Asia/Shanghai`。

发送状态保存在同目录的 `state.json`，只记录日期、来源摘要、发送时间、消息任务标识和结果状态，不保存完整对话或日报正文。

机器人编号和用户 ID 必须通过 `dws` 的只读查询或用户明确提供获得，不得猜测。

## 数据流

```text
手动触发
  -> 线程索引 + 会话 JSONL（只读）
  -> 标准化 JSON
  -> 项目级语义归纳
  -> Codex 使用复盘
  -> Markdown 日报
  -> 固定收件人校验 + 幂等检查
  -> 钉钉机器人单聊
  -> Codex 展示日报和发送状态
```

标准化 JSON 是解析器与 Skill 的唯一接口。钉钉发送器只接收最终 Markdown、日期和来源摘要，不接收原始会话数据。

## 日报内容契约

```markdown
# Codex 工作日报 - YYYY-MM-DD

## 今日概览
- 对话数量、涉及项目、已完成任务、未完成事项

## 项目进展
### 项目名称
- 目标与背景
- 今日完成
- 代码与文件变更
- 测试、验证与交付结果
- 关键决策

## 当前阻塞
- 阻塞事项、影响范围与解除条件

## 下一日待办
- [P0] 项目：事项；完成标准
- [P1] 项目：事项；完成标准
- [P2] 项目：事项；完成标准

## Codex 使用优化建议
### 建议标题
- 优先级：高 / 中 / 低
- 当天证据：脱敏后的对话或工作模式
- 优化建议：具体改进动作
- 可直接执行：模型档位、改写提示词、交接摘要或下一次操作示例

## 来源索引
- Codex 对话标题与项目目录
```

### 内容规则

- 所有工作区按项目分组，同一事项的重复讨论合并。
- 只保留有工作价值的摘要，不复制完整对话。
- 来源索引仅用于追溯，不包含原始消息正文。
- 敏感字段在进入语义归纳前脱敏，发送前再次扫描。
- 当天无有效工作内容时，生成并发送简短的“今日无可总结的 Codex 工作”日报。

### 下一日待办优先级

- `P0`：阻塞交付、明确要求下一日完成、生产故障或高风险事项。
- `P1`：应在下一工作日继续推进的核心任务。
- `P2`：优化、补充测试、文档整理等非紧急事项。

待办只能来自当天对话中的未完成工作或明确后续动作，不得凭空增加。每项必须包含所属项目和可验证的完成标准；没有下一日待办时明确写“无”。

## Codex 使用优化复盘

优化建议默认输出 `4` 至 `6` 条，最多 `8` 条，按预期收益排序。同类问题合并为一条；没有可靠证据时不为了达到数量下限编造建议。

### 必查维度

- **模型与推理强度**：结合线程实际使用的模型、任务复杂度、风险和结果质量，判断是否应使用日常快速或复杂深度档位，以及是否需要调整推理强度。
- **提示词质量**：按目标、上下文、约束、期望产物和验证方式检查用户提示，并提供可直接复用的改写版本。
- **上下文承接**：识别下一次继续工作所需的目标、已完成事项、当前状态、关键文件、验证结果、关键决策、阻塞和下一步。
- **对话边界**：同一项目、同一目标且依赖既有决策时建议继续原对话；目标、项目或交付物明显变化，或历史上下文已产生噪声时建议新开对话。

### 开放维度

发现其他有证据的高价值机会时可以一并输出，包括但不限于：

- 任务拆分与执行顺序。
- Skill、工具或 Codex 使用界面的选择。
- 测试与验证是否充分。
- 是否适合并行处理或拆成独立子任务。
- 需求澄清和完成标准。
- 文件、日志与外部资料的提供方式。
- 输出格式和反馈闭环。
- 重复操作是否值得沉淀为 Skill、脚本或 `AGENTS.md`。

### 单条建议契约

每条建议必须同时包含：

1. 问题或机会，以及高、中、低收益优先级。
2. 来自当天线程的脱敏证据；不复制完整提示词或敏感正文。
3. 明确的改进动作和适用原因。
4. 可直接执行的示例，例如模型能力档位、优化提示词、上下文交接摘要或新对话起始提示词。

模型建议优先使用当前环境能够确认的具体模型；无法确认时只给能力档位。提示词改写不得改变用户原始目标。对话管理建议必须明确“继续当前对话”或“新开对话”，新开对话时附最小上下文模板。

## 错误处理

### 阻止发送的错误

- 找不到任何可用线程索引或会话文件，且无法通过另一来源降级读取。
- 日期或时区无法解析。
- 标准化 JSON 结构无效。
- Markdown 未完成或发送前敏感信息检查失败。
- 机器人编号、收件人 ID 或钉钉认证缺失。
- 配置中的目标不满足固定单一收件人约束。

发生以上错误时不发送任何部分日报，并在 Codex 中报告具体原因。

### 可降级错误

单条 JSONL 事件损坏时跳过该事件，在标准化输出和日报中记录“采集缺口”。只要至少存在一条可验证的有效线程，日报仍可生成和发送。

### 发送错误

机器人发送接口不支持服务端幂等键。调用前先把稳定投递键记录为 `PENDING`：

- 返回明确成功结果时标记为 `SENT`。
- 返回明确未投递的参数或认证错误时标记为 `FAILED`，不自动切换机器人、收件人或发送通道。
- 超时、进程中断、响应无法解析等无法判断是否已投递的情况标记为 `UNKNOWN`，不自动重试，以避免重复消息。

已生成日报保留在本次 Codex 输出中，并报告完整错误与投递状态。后续再次触发相同来源内容时，`SENT` 直接跳过；`PENDING` 或 `UNKNOWN` 要求显式处理状态后才允许再次发送。

## 安全与隐私

- 只读取当前用户本机 Codex 数据，不上传原始对话。
- 只有最终 Markdown 日报发送到钉钉。
- 不在 Skill、测试夹具或 Git 仓库中保存真实机器人编号、用户 ID、认证信息或真实对话样本。
- 日报不得包含系统提示、开发者指令、内部推理、环境权限说明或工具原始输出。
- 固定收件人由个人配置决定，触发请求不能临时改变目标。
- 手动触发即为本次发送授权；此授权只适用于配置中的唯一收件人。

## 测试策略

Skill 创建遵循技能 TDD：先以不加载 Skill 的压力场景记录基线失败，再编写最小 Skill，随后用相同场景验证触发、解析、归纳和发送约束。

### 解析器测试

- 多种 JSONL 事件结构及未知事件兼容。
- 活动与归档会话合并。
- `Asia/Shanghai` 零点边界和 UTC 时间转换。
- 系统消息、工具日志和内部事件过滤。
- 敏感字段脱敏。
- 损坏事件跳过与采集缺口记录。
- 来源摘要稳定性。

### 日报契约测试

- 按项目归类和重复事项合并。
- 固定章节与 Markdown 格式。
- `P0/P1/P2` 判定及下一日待办完成标准。
- 无待办与无有效工作内容的明确输出。
- 超长内容按项目边界分片。

### Codex 使用复盘测试

- 模型与推理强度建议基于已观察事实或能力档位，不编造具体模型能力。
- 提示词改写保留原目标，并补齐缺失的上下文、约束、产物或验证方式。
- 同一目标建议继续原对话，目标切换或上下文污染时建议新开对话。
- 新开对话建议包含完整的最小交接模板。
- 必查维度和开放维度均能发现有证据的问题。
- 默认 `4` 至 `6` 条、最多 `8` 条；证据不足时允许少于 `4` 条。
- 每条建议均包含优先级、证据、行动和可直接执行示例。

### 发送器测试

- 固定收件人不可覆盖。
- 配置缺失时阻止发送。
- 相同来源摘要不重复发送，新增内容可发送更新版。
- 分片顺序和稳定投递键可重复计算。
- 发送前写入 `PENDING`，成功后写入 `SENT`。
- 超时或无效响应写入 `UNKNOWN`，且不自动重试。
- 状态文件不包含 Markdown 正文或敏感配置。

自动化测试使用模拟 `dws` 可执行文件，不向真实钉钉发送测试消息。安装完成后的首次用户手动触发用于真实链路验证。

## 验收标准

1. 输入“总结今天的 Codex 工作”可触发 Skill。
2. 默认汇总 `Asia/Shanghai` 当天所有本机会话，包括归档会话。
3. 输出不包含系统提示、工具原始日志、内部推理或未脱敏敏感字段。
4. 日报按项目组织，并包含当前阻塞及带 `P0/P1/P2` 的下一日待办。
5. 日报包含基于当天证据的 Codex 使用优化建议，通常为 `4` 至 `6` 条、最多 `8` 条，并允许发现必查维度之外的改进机会。
6. 每条优化建议包含优先级、脱敏证据、具体行动和可直接执行的示例。
7. Markdown 成功生成后无需二次确认，直接发送到配置中的唯一钉钉账号。
8. 本地发送账本阻止相同来源内容重复发送，有新增内容时会发送更新版；结果不明时不自动重试。
9. 关键提取或渲染失败时不发送不完整日报。
10. 钉钉发送失败或结果不明时记录准确状态并向用户报告，不因自动重试制造重复消息。
11. 单元测试和 Skill 压力场景验证全部通过，且测试过程不发送真实钉钉消息。
